# 손가락 복사기

직전 드래그를 유령 손이 반복하고, 지금 손가락은 다른 일을 맡는 1인 세로 모바일 협동 퍼즐 프로토타입입니다.
`index.html` 하나에 HTML·CSS·일반 JavaScript가 모두 들어 있으며, 외부 엔진·패키지·CDN·이미지·글꼴·오디오·네트워크 요청이 없습니다.

## 실행

- **데스크톱**: `index.html`을 브라우저로 엽니다. 마우스 드래그도 터치와 같은 규칙으로 처리합니다.
- **휴대폰**: 이 폴더를 정적 파일로 제공합니다. Python 3가 이미 있다면 이 폴더에서
  `python3 -m http.server 8000`을 실행하고, 같은 LAN의 휴대폰에서 `http://<PC의 IP>:8000/`에 접속합니다.
  파일 제공용일 뿐이며 게임 서버·계정·설치·배포는 필요 없습니다.

## 조작과 규칙 요약

| 행동 | 입력 | 결과 |
| --- | --- | --- |
| drag | 유령이 잡지 않은 블록의 터치 영역(지름 76 논리 px)에서 첫 포인터로 드래그 | 블록이 `내 손`(채워진 손) 소유가 되어 홈에 투영되고, 주황 점선 후보 경로를 녹화합니다. 기존 유령은 계속 재생합니다. |
| release | 정상적으로 손 떼기 | 유효하면 이전 유령을 해제하고 이 블록을 유령(테두리 손)이 끝 위치에서 3초 잡습니다. 그 뒤 역방향 D초 → 순방향 D초 → 끝 3초를 반복합니다. 무효하면 기존 유령을 그대로 둡니다. |
| cancel | `pointercancel`, 화면 숨김 | 후보와 수동 소유만 버립니다. 화면 숨김이면 전체를 일시정지합니다. |
| restart | `다시 하기` / `처음부터 다시 하기` | 진행 중이면 현재 방만 초기화합니다. 전체 완료 뒤에는 방 1·완료 0으로 돌아갑니다. |
| advance | 방 1 성공 뒤 `다음 방 →` | 방 2를 빈 상태로 시작합니다. 이전 기록은 넘어가지 않습니다. |
| resume | 일시정지 안내의 `계속하기` | 유령의 같은 재생 시점에서 이어갑니다. 이전 터치는 복원하지 않습니다. |

- 블록은 스프링 손잡이입니다. 아무도 잡지 않으면 초당 1.2u로 홈(u=0)에 돌아갑니다. 발판·스위치·목표는 블록을 **실제 손이나 유령이 잡고 있을 때만** 켜집니다.
- **방 1**: A(100,500)→(100,320), B(260,500)→(260,320). 두 블록이 모두 잡힌 채 u≥0.90인 상태가 연속 1초 지속되면 성공합니다.
- **방 2**: A(80,500)→(80,300)는 스위치이고 B(150,410)→(310,410)는 문(x=238)을 지나 목표로 갑니다. 잡힌 A가 u≥0.90이면 문이 열립니다. 잡힌 A u≥0.90과 잡힌 B u≥0.95가 동시에 연속 1초 지속되면 성공합니다.
  닫힌 문은 B 중심을 왼쪽 x≤210, 오른쪽 x≥266에 묶습니다. 수동·유령·복귀 모두 같은 규칙입니다. B가 문 구간에 걸쳐 있으면 닫힘을 보류하고 밀어내지 않습니다. 이 보류는 성공 조건을 우회하지 않습니다.
- 유효 기록: 경로 범위 4 논리 px 이상, 지속 1/30초 이상 30초 이하, 30Hz 표본은 시작·끝 포함 최대 902개입니다. 멈춘 탭, 짧은 이동, 취소, 30초 초과는 기록하지 않고 이유를 짧게 표시합니다. 전체 퍼즐 시간 제한은 없습니다.

## 자가검사

규칙 핵심(`createCore`)은 DOM 없이 동작합니다. 자가검사는 별도의 게임 인스턴스를 만들어 검사하므로 플레이 중인 게임과 화면에는 영향이 없습니다. 검사 경로를 화면에 정답으로 보여주지도 않습니다.

- **브라우저 콘솔**: 게임을 연 뒤 `FingerCopier.selfTest()`를 실행합니다. PASS/FAIL 목록과 요약이 출력되고 `{ pass, fail, lines }`를 돌려줍니다.
- **주소로 자동 실행**: `index.html?selftest`로 열면 로드 직후 콘솔에 결과를 출력하고, 오른쪽 아래에 통과 수 배지를 8초 동안 보여줍니다.
- **Node(선택)**: `module.exports`도 지원합니다. `<script>` 내용을 떼어 실행하면 `selfTest({ quiet: true })`를 부를 수 있습니다.

## 퍼즐 성립 여부 논리 검토

- **유령 없이는 풀 수 없음**: 실제 포인터는 하나이므로 `manual` 소유 블록은 최대 하나입니다. `ghost` 소유는 유효한 정상 종료로만 생깁니다. 비소유 블록은 위치와 관계없이 조건을 켜지 않습니다. 따라서 유령이 없으면 두 활성 조건이 동시에 참일 수 없습니다. 블록을 끝에 두고 손을 떼도 그 순간부터 비활성이며 1.2u/초로 돌아갑니다(1에서 0.90 아래까지 1/12초).
- **유령 + 손으로 풀 수 있음**
  - 방 1: A를 끝까지 옮겨 놓으면 유령이 A를 3초 잡습니다. 그동안 B를 끝까지 옮겨 1초 버티면 됩니다. 기획서 예시 일정으로 t≈1.98초에 성공합니다(시뮬레이션으로 확인).
  - 방 2: A를 스위치까지 옮겨 놓으면 유령이 3초 문을 열어 둡니다. 그동안 B를 문 너머 목표(x≥302)까지 옮겨 1초 버팁니다. 예시 일정으로 t≈1.85초에 성공합니다(시뮬레이션으로 확인).
    역할을 바꿔도 됩니다. 문이 열린 동안 B를 목표에 옮겨 바로 놓으면 유령 B가 목표에서 3초 버팁니다. 그사이 A를 직접 스위치까지 올리면 성공합니다.
    늦으면 유령 B는 되감다가 닫힌 문(x=266)에서 멈춥니다. 그 뒤 A를 올려 문을 열면 유령 B가 같은 지점부터 이어 가서 다시 목표에 도착하고 성공합니다(두 경우 모두 시뮬레이션으로 확인).
- 3초 끝 유지와 1초 성공 조건 사이에는 약 2초의 여유가 있습니다. 실제 손으로 이 시간이 충분한지는 아래 실기기 확인 항목입니다.

## 이번에 실제로 실행한 확인

- Node 22에서 자가검사 102/102 통과. 규칙 일부를 일부러 망가뜨린 변형 9종을 넣었고, 그중 8종을 자가검사가 FAIL로 잡았습니다.
  나머지 1종(성공 뒤 pointerup의 장면 잠금 검사 제거)은 성공 순간 포인터를 비우는 다른 경로가 같은 동작을 보장하는 중복 방어선이라 결과가 바뀌지 않았습니다.
- 헤드리스 Chromium(Playwright, 390×844 모바일 에뮬레이션, CDP 터치 이벤트)으로 다음을 확인했습니다.
  - 방 1과 방 2를 실제 드래그로 클리어, 닫힌 문에서 B가 x=210에 막히고 이유 문구가 나오는 것, touchcancel 뒤 기록 미생성
  - 숨김 이벤트 중 유령 시각 정지와 계속하기 뒤 재개, 전체 완료 뒤 처음부터 다시 하기
  - 가로 844×390에서 게임 영역이 잘리지 않고 버튼이 44px이며 세로 안내가 표시되는 것, 320×568 작은 화면 버튼 높이 48px
  - 외부 요청 0건(파일 자체 1건), 페이지 오류·콘솔 경고 0건
- 위 결과는 데스크톱 엔진의 에뮬레이션입니다. **실제 휴대폰에서는 아직 시험하지 않았습니다.** 재미나 이해도를 검증했다고 주장하지 않습니다.

## 구현 결정 (기획서가 정하지 않은 부분의 해석)

- 터치 영역은 블록 중심 반지름 38(지름 76)인 원입니다. 화면이 작아 이 크기가 44 CSS px보다 작아지면 판정 반지름을 넓힙니다. 두 영역이 겹치면 가까운 블록을 잡습니다.
- 드래그 목표 위치는 입력 이벤트에서 갱신하고, 블록 위치는 다음 1/60초 칸에서 투영·클램프합니다. 모든 입력과 숨김 이벤트는 처리 전에 그 시각까지 시뮬레이션을 먼저 진행합니다.
- 프레임 사이 실시간이 0.25초를 넘으면 나머지는 버립니다. 숨김 중 경과 시간은 보충하지 않습니다. 일시정지는 `visibilitychange(hidden)`과 `pagehide`로만 걸며, 데스크톱 창 포커스 이탈(`blur`)로는 걸지 않습니다.
- 성공하면 그 순간의 장면을 고정합니다. 블록·유령·타이머는 멈추고, 입력·녹화는 잠깁니다.
- 닫힌 문 쪽 판정은 이동 전 위치 기준입니다. 막힌 유령은 해당 칸 안에서 문에 닿는 시각까지만 진행한 뒤 멈추고, 열리면 다음 칸부터 한 칸씩 이어갑니다.
- 메시지 우선순위: 기록 무효·취소 같은 중요한 이유는 1.5초 동안 문 상태 같은 일반 알림에 덮이지 않습니다.
- 선택 범위의 유령 얼굴(테두리 손 안의 눈·입)만 넣었습니다. 규칙에는 영향이 없습니다.
